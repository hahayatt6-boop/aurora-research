# Aurora 多智能体协作规程

多智能体协作服务于研究质量、证据可追溯性和儿童与家庭安全。代理可以协助收集、整理和质疑材料，但不能绕过研究模板、隐私边界、反证要求或 MVP 准入门。

## 角色帽子

| 角色 | 主要职责 | 不应承担 |
| --- | --- | --- |
| 主控与落库代理 | 拆分任务、约束文件范围、串行合并、更新索引、运行验证 | 用证据不足的材料生成方向性结论 |
| 研究代理 | 查找一手来源、记录获取日期、语境和局限 | 把二手摘要或 AI 输出当作事实 |
| 整理代理 | 格式化 Markdown、归并草稿、运行本地脚本 | 单独改变研究状态或置信度 |
| 反方审阅代理 | 挑战主要主张、寻找反证和替代解释 | 审阅自己刚生成的结论 |
| 校验代理 | 运行测试、仓库校验和链接检查 | 替代研究判断、伦理判断或 MVP 授权 |

这些是责任帽子，不绑定具体工具。Codex、OpenCode、Claude Code 或其他代理都必须遵守同一套输入、写入和验证规则。

## 模型不可用时的降级

若指定审阅模型不可用，主控代理必须记录失败原因、命令或错误摘要，并切换到可用的独立审阅路径。可接受的降级路径包括本地 OpenCode/opencode 的高能力模型、可用的 Codex 冷启动审阅代理，或其他已明确记录来源的本地 advisor。

降级审阅必须满足：

- 不伪称来自原指定模型。
- 记录替代模型、审阅输入范围和局限。
- 仍使用独立上下文，且 `reviewer_id` 不得等于 `original_author_id`。
- 对方向、MVP 或 accepted ADR 相关结论保持项目负责人门。

## 隐私入库前门

任何疑似包含儿童、家庭、学校、联系方式、健康或精确位置标识的材料，不得写入仓库文件、协作模板、测试 fixture、diff、提交历史或代理交接记录。

禁止入库的材料包括但不限于：

- 儿童或家庭成员姓名、昵称与可关联身份组合。
- 邮箱、手机号、社交账号、家庭地址。
- 学校、班级、精确活动地点或可重新识别的场景描述。
- 健康、诊断、心理状态、家庭关系等敏感背景。
- 录音、照片、视频、原始访谈逐字稿。

允许入库的只有不可识别摘要、来源元数据、公开材料引用和经批准研究方案处理后的去标识记录。校验脚本只是最后防线，不是去标识化流程。

## 文件所有权

- 一个任务应声明允许修改的文件范围。
- 多个代理不得同时修改同一研究记录。
- 权威文件的最终合并由主控与落库代理串行完成。
- 中间草稿不能长期保留，除非明确标注状态、局限和后续处理人。

## 标准工作流

1. 用 [`templates/agent-task.md`](../../templates/agent-task.md) 定义任务目标、角色、输入、允许文件和禁止材料。
2. 先执行隐私入库前门；不合格材料直接停止并转仓库外处理。
3. 研究代理只登记来源和可追溯事实。
4. 整理代理把材料放入 `evidence/`、`hypotheses/`、`research/` 或 `decisions/` 的兼容结构。
5. 重大结论由独立代理使用 [`templates/adversarial-review.md`](../../templates/adversarial-review.md) 审阅。
6. 主控与落库代理串行合并，更新索引和关系链接。
7. 运行验证命令。

## 独立反方审阅

以下状态推进必须有独立反方审阅记录：

- 研究报告进入 `review` 或 `complete`。
- 假设进入 `supported`、`weakened`、`rejected` 或 `inconclusive`。
- 决策记录进入 `accepted`。
- MVP、原型、访谈招募或外部发布相关结论。
- 会改变 Aurora 方向的重大建议。

`unresolved` 审阅结论不能被静默忽略，必须降低置信度、进入未知项、阻止状态推进，或形成明确下一步。

## MVP 准入

`mvp/` 不是草稿区。除 `mvp/README.md` 外，任何 MVP 蓝图必须引用已接受的授权 ADR、已完成的研究报告、相关假设和完整安全审阅。研究报告本身不授权产品工作。

## 升级条件

遇到以下情况必须停止自动推进并回到项目负责人：

- 需要处理疑似可识别儿童、家庭、学校或联系方式信息。
- 研究结论会改变 Aurora 方向、MVP 准入或产品承诺。
- 代理之间对证据可靠性、反证解释或置信度存在实质冲突。
- 只有低可靠证据，却被要求支持重大决策。
- 需要用户招募、访谈执行、外部发布或产品实验。
